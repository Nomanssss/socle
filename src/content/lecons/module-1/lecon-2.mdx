Une seule commande est indispensable au démarrage.

```bash
npm run dev
```

Elle lance un serveur local sur `http://localhost:4321` qui se recharge à chaque enregistrement de fichier. Gardez-la ouverte pendant que vous écrivez : c'est tout ce dont vous avez besoin pour produire du contenu.

## La liste complète

| Commande | Quand s'en servir | Ce qu'elle produit |
| --- | --- | --- |
| `npm run dev` | En permanence pendant l'écriture | Rien : un serveur local |
| `npm run build` | Avant de publier | Le site dans `dist/` |
| `npm run preview` | Pour vérifier le build | Rien : sert `dist/` |
| `npm run slides` | Pour les présentations | Un PDF par leçon dans `slides/` |
| `npm run slides:html` | Pour projeter au navigateur | Un HTML par leçon dans `slides/` |
| `npm run bundle` | Pour transmettre le cours | `dist/` complet : site + slides |
| `npm run brand` | Après un changement de charte | Les fichiers de style et les polices |

## Deux choses qui surprennent la première fois

**`npm run build` est aussi votre validateur.** Il échoue si l'en-tête d'une leçon est invalide — champ obligatoire manquant ou mauvais type. Lancez-le avant de publier, même si vous n'avez pas besoin du site : c'est le seul moment où le template vérifie vos fichiers.

**`npm run brand` se lance tout seul.** Il est branché en amont de `dev`, `build` et `slides`. Vous n'avez donc quasiment jamais à l'appeler à la main : un simple `npm run dev` suffit après un changement de couleur.

## Ce qu'il faut savoir avant de générer des slides

L'export en PDF et en PowerPoint **nécessite Chrome ou Chromium installé** sur la machine. L'export HTML, non. Si `npm run slides` échoue en parlant de navigateur, c'est de cela qu'il s'agit — et `npm run slides:html` vous dépanne en attendant.
