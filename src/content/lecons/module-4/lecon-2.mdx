Vous voulez mettre le cours en ligne, mais ouvrir les leçons au fur et à mesure. C'est à cela que sert le verrou.

## La règle

Listez les leçons à fermer dans `socle.config.json` :

```json
"locked": ["module-4/lecon-4"]
```

Puis `npm run build`. **Déverrouiller, c'est retirer la ligne et reconstruire** — rien d'autre à toucher.

L'identifiant est le chemin de la leçon sans `.mdx`, tel qu'il apparaît dans l'URL. Les formes approximatives sont tolérées : `src/content/lecons/module-4/lecon-4.mdx`, `/module-4/lecon-4/` et les antislashs de Windows donnent tous le même résultat.

> **Il y a un exemple en fonctionnement dans ce cours.** La dernière leçon du module est verrouillée : regardez-la sur l'accueil et dans la barre latérale — elle est grisée, avec un cadenas, et ne réagit pas au survol.

## Ce que le verrou fait exactement

| | Leçon ouverte | Leçon verrouillée |
| --- | --- | --- |
| Page générée dans `dist/` | ✓ | **✗ (404)** |
| Contenu présent dans le paquet livré | ✓ | **✗** |
| Slides (HTML et PDF) | ✓ | **✗** |
| Listée au sommaire de l'accueil | ✓ | ✓ grisée, « Bientôt disponible » |
| Listée dans la barre latérale | ✓ | ✓ grisée, avec un cadenas |
| Comptée dans la progression du module | ✓ | ✗ |
| Atteignable par « Précédent / Suivant » | ✓ | ✗ — le parcours l'enjambe |

## C'est un vrai verrou, pas un masquage

C'est le point important, et il mérite d'être compris avant de publier.

La leçon est écartée **au moment de fabriquer les pages**. Aucune page n'est donc produite : il n'y a pas d'URL à deviner, et le texte de la leçon n'est nulle part dans le dossier livré. Ses présentations ne sont pas générées non plus.

Sur un site statique, c'est la **seule** forme de verrou qui tienne. Tout contrôle qui se contenterait de cacher un lien, ou de demander un mot de passe en JavaScript, se contournerait en lisant la source de la page. Ici, il n'y a rien à contourner : le contenu n'a pas été publié.

## Deux détails qui ont leur importance

**La progression exclut les leçons verrouillées.** Un module de quatre leçons dont une est fermée compte sur trois. Sans cela, il resterait bloqué à 75 % sans que l'apprenant puisse rien y faire.

**Une faute de frappe ne verrouille rien** — et sans avertissement, vous croiriez une leçon protégée alors qu'elle est en ligne. Le build vous prévient donc :

```
⚠ socle.config.json → « locked » : aucune leçon ne correspond
  à « module-9/lecon-42 ». Ces entrées ne verrouillent rien.
```

Surveillez cette ligne : c'est votre seul filet.

## En développement, il faut redémarrer

Un changement de `locked` n'est **pas** détecté à chaud par `npm run dev`. Arrêtez le serveur et relancez-le, sinon vous verrez l'ancien état et conclurez à tort que le verrou ne marche pas.
